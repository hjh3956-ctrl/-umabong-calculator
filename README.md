# 우마봉 전략 계산기

사진으로 6명의 능력치를 입력하고 단독·반반·세 명 동액 배분의 회수액과 위험을 비교하는 모바일 중심 정적 웹 앱입니다.

## 사용 순서

1. **새 경기**를 누르고 능력치 사진 최대 6장을 선택합니다. 사진 선택 영역 아래의 **능력치·보유 코인 적용**을 누릅니다. 오른쪽 위 보유 코인도 함께 읽으며, 사진마다 금액이 다르거나 확실히 읽지 못하면 자동으로 덮어쓰지 않습니다. 사진별 세부 항목은 펼쳐 확인하고 누락 항목을 채웁니다. 보유 코인은 사진의 축약 표시 기준이므로 직접 수정할 수 있습니다.
2. 보유 코인과 게임에서 **실제로 누른 더블**을 설정하고 계산합니다. 기본 목적은 이번 판 평균 코인 최대화입니다. 손실 한도를 따로 설정할 수 있습니다.
3. 추천과 금액별 확률을 확인하고 **이 배분 선택**을 누릅니다. 게임 내 투자는 직접 진행합니다.
4. **경기 전 예측 저장**으로 현재 투자 조건을 고정합니다. 경기 후 검증 기록에 실제 1~6등, 더블 여부, 확인 가능한 구간의 부스트를 입력합니다.

계산 화면에서 입력을 바꾸면 이전 추천이 잠기며 다시 계산해야 합니다. 기록은 브라우저에 저장됩니다. JSON 내보내기/불러오기로 백업할 수 있고 가져온 기록은 기존 ID를 덮어쓰지 않습니다. 사이트 주소나 기기를 바꾸면 자동 이전되지 않습니다.

## GitHub Pages에 올리기

1. GitHub에서 `umabong-calculator` 같은 빈 저장소를 만들고 이 폴더의 파일을 업로드합니다. `.github/workflows/pages.yml`과 `dist/ocr/`도 포함합니다. 무료 개인 계정은 공개 저장소로 Pages를 이용할 수 있습니다.
2. 저장소 **Settings → Pages → Build and deployment → Source → GitHub Actions**를 선택합니다.
3. `main` 브랜치에 커밋하거나 **Actions → Verify and deploy Pages → Run workflow**를 실행합니다.
4. 배포 성공 후 Settings → Pages에 표시되는 주소로 접속합니다. 기본 형태는 `https://계정.github.io/저장소/`입니다.

설정 근거: [GitHub 공식 Pages 사용자 지정 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).
계산과 OCR은 정적 파일로 동작하며 별도의 서버·API 키가 필요 없습니다. 모든 앱 경로는 상대 경로이므로 저장소 하위 URL에서도 동작합니다. HTML 파일을 직접 더블클릭하지 말고 웹 주소로 접속하세요.

## 계산에 포함하는 것

- 지능별 구간 발동률, 부스트 **0~3회** 및 초·중·후반 **8개 패턴**. 6명 전체 262,144조합을 같은 비중으로 세지 않고 확률로 가중합니다.
- 투자 방식마다 단독 최대 투자 컨디션 패널티를 다시 적용합니다. 같은 부스트 조합에서 단독이 더 받음 / 반반이 더 받음 / 동액을 비교해 합계 100%로 표시합니다.
- 평균 최종 코인, 코인 증가·감소·전액 손실, 받을 잔액별 확률. 동률 투자의 패널티 회피가 개별 투자 손실 방지를 뜻하지 않습니다.
- 원본에서 검증한 성향 적용 조건, 체력조절 공유 카운터, 같은 틱의 결승선 통과 순서.
- 저장 시점의 예측과 실제 순위를 분리하고 우승·2등 후보 적중, 잔액 감소, 지능별 관측 부스트를 누적 비교합니다. 모르는 부스트는 미발동으로 세지 않습니다.

추천은 설정한 목적과 손실 한도 안에서 정해진 후보 배분을 비교합니다. 모든 비율의 전역 최적 투자라고 주장하지 않습니다. 단독·반반·세 명 카드에서는 각각 전액 동액 배분 중 평균 코인이 가장 큰 후보를 보여줍니다.

## 검증과 한계

Android 추출 경로와 대조한 모델입니다. **실제 게임의 장기 승률을 보증하는 수치가 아닙니다.** 실제 난수 시드, 서버 보정, 다른 앱 버전은 확인하지 못합니다. 모델상 0%도 실게임의 안전 보장은 아닙니다. 과거 결과를 맞추기 위해 지능별 발동률을 임의 보정하지 않습니다. 영상 자동 판독 기능은 없습니다.

Node.js에서 `npm test`를 실행하면 원본 기준 100개 전체 주행(11,488로그), 43개 확률 분포, Worker 후보, 신규 전략 비교, 기록 보존, 입력 바인딩 등을 확인합니다. 패키지 설치 없이 실행됩니다. 브라우저 렌더링 검사는 별도이며, 이 배포 준비 과정에서는 수행하지 못했습니다.

OCR 원본 사진 회귀 검사는 별도 데이터가 필요하므로 기본 테스트에 포함하지 않습니다. `npm ci` 후 원본 사진 데이터를 준비한 환경에서 `npm run test:ocr-fixtures`로 실행합니다. 기존 사진 파서·자동 성향 확인·부분 입력 동작 테스트는 기본 테스트에 포함됩니다.

배포 파일은 `dist/`에 있습니다. `engine.mjs`는 주행·지급, `strategy.mjs`는 동일 부스트 조건 비교, `worker.mjs`는 백그라운드 계산, `history.mjs`는 사전 예측과 결과 기록입니다. 큰 OCR 실행 파일과 언어 모델은 자동 배포 시 `npm ci`와 `npm run prepare:ocr`로 고정된 버전을 준비합니다. 로컬 실행도 같은 두 명령으로 준비하세요. OCR 라이선스와 고지는 `dist/ocr/`에 보존되어 있습니다.
